# Labeled terminal links

OSC 8 attaches a URI to printed terminal cells. The label does not need to
contain a visible URL. Opening and closing a link does not open anything on
Android; the user must tap its cells, with `terminal-onclick-url-open` enabled.
The URI goes through the existing `ShareUtils.openUrl` Android `ACTION_VIEW`
handler. No new scheme allowlist or automatic launch path is introduced.

## Source and adaptation

Metadata storage, explicit IDs, clearing, reflow, history and Unicode handling
adapt [upstream PR5390](https://github.com/termux/termux-app/pull/5390),
commit `6fb4ee65d468c21882fa27b9305e622c6a2f8905`. Its
`TerminalEmulator.MAX_HYPERLINKS` policy retains at most 1024 URI entries and
sweeps unreachable IDs before reuse; a full table leaves new cells unlinked.
The parser retains this fork's existing OSC string bound.

Fold integration additionally covers batched ASCII output and immutable
DEC 2026 frames. A completed frame copies both cell IDs and their URI table,
so recycling a live ID cannot change an unfinished frame's tap destination.
The application resolves labels in the active session. Ordinary detected URLs
use the same presented screen, and the existing disabled-click setting still
disables both routes.

## Verification

`HyperlinkTest` covers OSC terminators, explicit IDs, wide/combining text,
overlapping copies, erase/reset, linked spaces, reflow/history, table
exhaustion/reuse, alternate screens, ASCII overwrite and completed-frame
destination retention.

`KeyboardNavigationTest.labeledLinksUseActivePaneCompletedFrameAndExistingClickPreference`
dispatches real terminal-view touch events and inspects the resulting Android
view intents. It checks session switching, completed rather than pending
targets, disabled clicks and ordinary URL fallback. The test report includes
plain-label and linked-label PNGs; pixels intentionally remain unchanged.
These are Android test-runtime checks, not physical Fold installation or
browser-app acceptance.
